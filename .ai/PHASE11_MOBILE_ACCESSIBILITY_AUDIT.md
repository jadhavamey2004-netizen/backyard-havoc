## Accessibility review matrix (baseline evidence)

| Issue | Criterion | Current evidence | Severity | Correction | Verification |
|---|---|---|---|---|---|
| Gameplay lacks touch locomotion | Target Size; Pointer Cancellation; Name/Role/Value | Touch can aim/action the Canvas but cannot move the player. No mobile controls exist. | High | Add named native movement buttons backed by existing player input. | Touch hold/release movement, simultaneous Canvas action, pause/cancel, and responsive hit-test scenarios. |
| Touch end is not associated with its originating finger | Pointer Cancellation; Dragging Movements | Global `touchend` uses `changedTouches[0]`; engine has no pointer ID. | High | Use Pointer Events, capture, an action pointer ID, and a separate set/map of movement pointers. | Two-pointer movement/action and unrelated-finger release tests. |
| Affiliate target was undersized | Target Size | Previous rendered minimum was 38px; center hit-test showed the anchor received input. Local correction raises it to 48px. | Medium | Preserve the 48px minimum and secondary visual treatment. | Affiliate E2E across desktop, touch, portrait, landscape, scrolling, progression, and keyboard activation. |
| Small supporting text | Resize Text; Contrast | Current CSS includes sub-12px HUD labels, challenge requirements/rewards, and disclosure. | Medium | Measure real rendered sizes and stable foreground/background contrast; enlarge only text that demonstrably fails the chosen criterion. | Browser-measured color ratios, 200% text-size test, 320px reflow, and visual screenshots. |
| Focus inside clipped panels | Focus Order; Focus Visible; Focus Not Obscured | Screen panels use internal scrolling and a modal Tab loop; no explicit focus-scroll listener exists. | Medium | Preserve native scrolling unless tests prove focus is obscured; then add narrowly scoped scroll-into-view behavior. | Keyboard traversal at 200% text and narrow Results/Garage/Challenges layouts. |
| Keyboard access to gameplay and touch controls | Keyboard; Focus Order; Focus Visible; Name/Role/Value | Phase 9 provides semantic menu controls, modal focus behavior, Canvas focus on gameplay return, and keyboard gameplay input; no touch movement controls existed. | Medium | Preserve Phase 9 focus/input contracts; use named native touch buttons with announced pressed state and the existing movement API. | Desktop keyboard regressions, keyboard activation of movement buttons, touch-state assertions, and the Phase 9 post-Resume Space regression. |
| Reduced-motion Canvas pulses | Animation from Interactions; Three Flashes or Below Threshold | Four presentation-only Canvas pulses continue independently of the setting. | Low | Use static values under reduced motion; retain the skip prompt, defeat state, danger state, and idle-ball hint. | E2E reduced-motion state/render assertions and existing OS/override regression. |
| Contrast/color-state evidence incomplete | Contrast (Minimum); Non-text Contrast | CSS contains stable token pairs, but no contrast measurements are recorded in the baseline. | Small-screen page clipping | Reflow | `html/body` have a 320px minimum; `#app` clips overflow while screen panels scroll internally. | Medium | Keep 320px supported and ensure every HTML panel/action remains reachable without horizontal page scroll. | 320px checks for Title, Settings, Garage, Challenges, and Results. |

## Phase 11 implementation and verification findings

- `src/main.js` now has one Pointer Events path for mouse/touch/pen. It captures one Canvas action pointer ID and tracks movement pointers independently. Keyboard and touch movement sources are aggregated before they reach the existing Player movement API.
- The two native movement buttons are gated by touch capability and active gameplay state, use safe-area-aware fixed placement, and are children of the UI-inert gameplay stage. They remain hidden on ordinary desktop and outside gameplay. Their press state is announced with `aria-pressed`.
- Canvas action cancellation, movement release, and aggregate input cancellation are wired to pointer up/cancel/lost capture, blur, hidden page, Pause, Restart, Main Menu, and Game Over. A cancel cannot resolve a kick; a following physical pointer-up has no remaining owner.
- The new `chromium-touch` project uses Playwright 1.63.0's explicit `isMobile`, `hasTouch`, `deviceScaleFactor`, and viewport options. Desktop Chromium remains configured for the rest of the suite.
- Touch browser tests cover Play/intro, movement hold/release in both directions, keyboard activation and focus of the movement buttons, simultaneous movement and Canvas action, charge/release, cancellation, visibility loss, Pause/Restart, Main Menu/Game Over cleanup, target hit-tests, and 960×540 pointer mapping after resize at DPR 2.
- Desktop browser tests cover mouse aim/click/Power Shot, A/D, arrows, Shift, Space intro skip, and Escape Pause/Resume. Existing Phase 8–10, affiliate, UI focus, and progression suites remain enabled.
- At a 320×800 viewport with a 200% root-size simulation, Playwright checks Title, Settings, Garage, Challenges, and Results, captures screenshots, checks focus visibility, and confirms no horizontal page overflow. The required mobile/tablet/desktop viewport matrix checks each of those panels and interactive target heights.
- The reduced-motion Canvas regression confirms a static intro prompt and a retained danger indicator at fixed alpha. Game rules, timings, logical coordinate scale, DPR ceiling, and resource caps are unchanged.
- Browser-computed contrast evidence covers representative HTML text and control boundaries; the attached measurement report is not a formal WCAG certification. Physical devices, assistive-technology usability, nonzero hardware safe-area insets, and exhaustive Canvas contrast remain external/human validation items.

Final local test totals, exact contrast ratios, mobile frame/resource snapshot, and GitHub/Preview provenance are recorded in `.ai/PHASE11_MOBILE_ACCESSIBILITY.md` and the final review handoff after the complete run.
